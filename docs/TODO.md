# Відкриті питання й рішення, які треба ухвалити

Тут лежить те, що я **не вирішую сам**: місця, де можливі кілька шляхів і
вибір змінює архітектуру. Дрібні технічні рішення приймаються на місці й
описуються в коді або в `docs/`.

## Потребує рішення

### 1. Ліцензія проєкту
Ще не вибрана. Project Dalian під MIT, а ми звіряємося з їхніми
специфікаціями форматів. Треба визначитися до першого публічного релізу.

### 2. Формат власного інтерфейсу
Flash не повторюємо (рішення ухвалене). Але чим його замінити — власним
мінімальним UI на наших примітивах чи готовою бібліотекою — не вирішено.
Впливає на шрифти, меню й HUD одразу.

### 3. Сумісність із оригінальним протоколом
Чи має `openbf2` під'єднуватися до **оригінальних** серверів BF2 1.5
(побайтова сумісність протоколу), чи лише до власних? Перше значно дорожче
й прив'язує до кожної дрібниці оригіналу; друге дозволяє чистіший дизайн.
Поки роблю **читання оригінального формату** (щоб розуміти й тестувати), але
не гарантую сумісність.

### 4. GameSpy / майстер-сервер
Оригінал ходив у GameSpy, якого вже немає. Варіанти: свій майстер-сервер,
сумісність із BF2Hub/OpenSpy, або лише прямі під'єднання. Не вирішено.

### 5. PunkBuster
Не реалізовуємо (античит з ядром і серверною інфраструктурою). Треба
вирішити, чи вдавати його наявність для сумісності зі старими клієнтами.

## Прийняті рішення (для довідки)

- **SDL3 + SDL_GPU** замість OpenGL — `docs/research/01-render-backend.md`
- **Bink і Flash не повторюємо** — логіка 1:1, показ свій —
  `docs/research/03-startup-and-menu.md`
- **Редакторська гілка `.con` рівня** замість скомпільованого
  `terraindata.raw` — `docs/formats/level.md`
- **Windows-збірка відкладена**, база лишається портованою — `CLAUDE.md`

## Знайдено, але ще не використано

- **Лінукс-сервер 1.5 із повними символами й DWARF** —
  `Game Files/OtherFiles/linuxded/bin/ia-32/bf2`, імпортований у Ghidra.
  68 921 символ. Це головний інструмент для netcode; поки взято лише API
  BitStream. Див. `docs/research/04-netcode.md`.
- **`bf2editor_and_tools`** (145 МБ) — офіційний редактор DICE. Не досліджено.
  Найімовірніше містить документацію форматів і, можливо, експортери.
- **Таблиці компресії векторів** у секції даних ELF
  (`m_compressionVectorBitTable*`) — читаються напряму, ще не витягнуті.

## Технічний борг

- Немає відсікання невидимого: рівень малює всі 2.35 млн трикутників щокадру.
- Немає лайтмап терену — освітлення рівне.
- ~~Екранні прямокутники малюються 3D-пайплайном~~ — зроблено: `renderOverlay`
  з альфа-змішуванням, без глибини й освітлення.
- Звук не реалізовано: 37 команд `Sound.con` (`objecttemplate.soundFilename`,
  `sound.masterVolume`) лишаються без обробника.
- Меню не інтерактивне: список карт малюється, але вибрати карту мишею
  не можна — немає обробки вводу поверх `ControlMap`.
- Тривалість заставок узята умовною: Bink не декодуємо, справжніх
  тривалостей не знаємо.
- `stb_image` зібрано лише з PNG — якщо знадобиться JPEG, вмикати окремо.
