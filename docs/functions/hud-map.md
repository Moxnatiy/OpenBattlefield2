# Карта: розмір, положення й звідки беруться `MapFullSize`/`MapMinSize`

Карта в HUD — не «мінікарта і окремо велика карта», а **один вузол зі
своєю парою «ціль / поточне»**. Номер стану HUD задає ціль, а розмір
їде до неї згладжуванням; обидві змінні показу виводяться вже з
поточного розміру, а не зі стану.

Через це в оригіналі перехід мінікарта ↔ велика плавний, і рамки
(`MinSizeAlpha`, `MapFrameOpen`) перемикаються не миттєво: доки розмір у
дорозі, **не ввімкнена жодна** з двох змінних.

Джерела: `BF2.exe`, 0x777dc0 (стан → ціль) і 0x77c330 (крок і виведення).
У коді — `src/hud/include/obf2/hud/map_node.h`.

## Поля вузла карти

| зсув | що це | звідки |
|---|---|---|
| +0x68c | `MapFullSize` | виводиться з розміру, 0x77d3f8 |
| +0x68d | `MapMinSize` | там-таки |
| +0x68e | режим командира, він же індекс у таблиці масштабів | |
| +0x690 | режим екрана появи | 0x777f9a |
| +0x691 | режим командира | 0x7781b0 |
| +0x692 | режим меню (стани 0x11/0x12) | 0x778299 |
| +0x694 | `1 - висота цілі / висота екрана` (у командира навпаки) | 0x77cf10 |
| +0x698 | поточний масштаб; +0x6d0 — його номер | |
| +0x776 | чи розмір доїхав (минулого кадру) | |
| +0x778, +0x77c | ціль: ширина й висота | |
| +0x780, +0x784 | ціль: X і Y | |
| +0x788, +0x78c | `setMiniPos` | 0x75f319 |
| +0x798, +0x79c | `setMiniSize` | вживається в 0x777e4f |
| +0x7a8, +0x7ac | `setCommanderPos` | |
| +0x7b0, +0x7b4 | `setCommanderSize` | |
| +0x7b8, +0x7bc | `setMaxiSize` | 0x75f423 |
| +0x7c0, +0x7c4 | `setMaxiPos` | 0x75f555 |
| +0x7f8 | «стати одразу», без згладжування | |

Поточні позиція й розмір лежать не в самому вузлі, а в спільних комірках
(`FUN_0065ddd0` — позиція, `FUN_00659990` — розмір). До позиції додано
пів екрана 800×600: `setMiniPos 197/-300` — це (597, 0), і рамка
`MapFrame` стоїть на (596, 0).

## Стан HUD → ціль (0x777dc0)

| стан | ціль |
|---|---|
| 0 — бій | `setMiniPos` / `setMiniSize` |
| 1 — екран появи | `setMaxiPos` / `setMaxiSize`, прозорість стала (1.0, значки 0.5) |
| 2 — велика карта | те саме, але прозорість із налаштувань `MenuMapAlpha`, `MenuMapIconAlpha` |
| 15 (0xf) — командир | `setCommanderPos` / `setCommanderSize`, лише якщо режим ще не ввімкнено |
| 17, 18 (0x11, 0x12) — меню загону й командира | `setMaxiPos` / `setMaxiSize`, прозорість 0.9 |
| решта, зокрема 19 (`MapMenuShow`) | ціль не чіпають |

Стан 19 — це швидке меню масштабу (`HudElementsMapMenu.con`: кнопка
`MapZoom` і підпис), воно лягає **поверх** карти. У даних у ньому лише
два вузли, і це не помилка складання.

## Крок анімації (0x77c330)

```
значення += (1 - e^(-6*dt)) * (ціль - значення)
```

Показник затискається в [-10, 10] (`FUN_00402ee0`), ближче ніж 0.1 до
цілі — просто стаємо на неї. Та сама швидкість 6.0 веде позицію, розмір і
прозорості.

## Виведення змінних показу (0x77d3a0)

```
якщо розмір >= maxiSize - 3 по обох осях  -> MapFullSize
інакше якщо розмір <= miniSize + 3        -> MapMinSize
інакше                                     -> жодної (розмір у дорозі)
```

У режимі командира (стан 0xf) порівняння йде з `setCommanderSize`.

## Чого ми ще не знаємо

* Обрис: мініатюра кругла, велика квадратна — **звідки рушій бере круглу
  маску, не з'ясовано**. Ми беремо обрис за `MapMinSize`.
* Прозорості `+0x700`, `+0x704`, `+0x70c`, `+0x710`, `+0x718` (карта,
  значки, підсвітка) ведуться тією самою анімацією, але ми їх поки не
  відтворюємо.
* Блок виведення в оригіналі виконується не завжди: він пропускається,
  поки мінікарта ще довертає компас (+0x774). Цього прапорця ми не
  ведемо, тож рахуємо щокадру.
* `MapFullSizeAndNotSpawnShow` у 0x4668f0 має ще й третю умову —
  `[0xa10890]->vtbl[0x24c]()->+0x24f`; що це за поле, не з'ясовано.

## Кут компаса

`MinimapDelayedMapAngle` — це поле **+0x760** вузла карти; ім'я склеює
0x780a49 з назви вузла і рядка `%sDelayedMapAngle` (0x930c70). У даних
його вживає єдиний вузол — `MapCompass`
(`setPictureNodeRotateVariable`).

Ведуть його два згладжувачі поспіль, обидва зі швидкістю 9.0 (стала
-9.0 за 0x930334, вживається в 0x77c542 і 0x77c68b):

```
+0x770 = atan2(напрямок.x, напрямок.z)        0x751d8b -> 0x772470
+0x75c -> доводиться до +0x770                0x77c4f4..0x77c569
+0x764 = wrapToPi(+0x75c)                     0x77c57f
+0x760 -> доводиться до +0x764                0x77c632..0x77c6b2
```

Доводка йде найкоротшою дугою: напрям дає `FUN_00772310` (0x772310) з
порогом 0.001, довжину — `FUN_00772410` (0x772410), а обгортання в
(-pi, pi] — `FUN_007722d0` (0x7722d0).

Похитування після різкого повороту (поля +0x724, +0x758, +0x768, +0x775,
+0x777 і синус із частотою 4.5 за 0x930330) в оригіналі є, але **ми його
не відтворюємо**: не звірено.
