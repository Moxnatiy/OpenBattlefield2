## Розкладка

Класичний DDS: підпис `"DDS "`, заголовок 124 байти, далі дані рівнів підряд.
Формат визначається з `DDS_PIXELFORMAT` за зсувом 76:

- `DDPF_FOURCC` (0x4) → `DXT1`/`DXT3`/`DXT5`;
- `DDPF_RGB` (0x40) → дивимося на кількість біт і маски каналів;
- інакше 8 біт → одноканальна.

## Дві пастки

**Стиснені рівні рахуються блоками 4×4 навіть коли менші за блок.** Рівень
1×1 у DXT5 займає цілі 16 байтів, а не частину блока. Якщо порахувати
«за пікселями», зсуви всіх наступних рівнів поїдуть — і текстура
перетвориться на шум.

**Кількості рівнів у заголовку довіряти не можна.** У грі є файли з
`mipCount = 0`, які насправді мають один рівень. Парсер бере стільки рівнів,
скільки фізично влізло у файл, і зупиняється — тому обрізаний файл дає
коротший ланцюжок, а не читання за межами буфера.

## Який слот матеріалу — базовий колір

Матеріали мешів мають до чотирьох слотів текстур. Розподіл суфіксів по
4524 матеріалах усіх `.staticmesh` гри не лишає сумнівів:

| Слот | Суфікс | Разів | Що це |
|---|---|---:|---|
| 0 | `_c` | 4524 | базовий колір |
| 1 | `_de` | 4391 | детейл |
| 2 | `_deb` / `_di` | 3251 / 945 | нормаль детейлу / бруд |
| 3 | `_pow36` / `_deb` / `_cr` | 2604 / 939 / 131 | відблиск / нормаль / тріщини |

Це підтверджують і самі назви technique: `BaseDetailNDetail`,
`BaseDetailDirtNDetail`, `BaseDetailDirtCrackNDetailNCrack` — вони буквально
перелічують слоти по порядку. Рендер поки бере лише слот 0.

## Перевірка

```bash
./build/macos-arm64-debug/tools/texture_info/texture_info "Game Files/mods/bf2" --all
./build/macos-arm64-debug/tools/mesh_info/mesh_info "Game Files/mods/bf2" --materials
```

Текстурований об'єкт на екрані:

```bash
./build/macos-arm64-debug/src/app/openbf2 \
  --mesh "objects/staticobjects/common/com_objects/crates/woodencrate_3m/meshes/woodencrate_3m.staticmesh"
```

BC1/BC2/BC3 віддаються на GPU як є — Metal на Apple Silicon їх підтримує,
тому розпаковувати на CPU не доводиться. Формат перевіряється у рантаймі
через `SDL_GPUTextureSupportsFormat`.
